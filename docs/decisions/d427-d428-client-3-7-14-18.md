A part of [the decisions](README.md); each decision has one line in [the index](../decisions-index.md).

## D427: Client 3.7.14.18, measured against 3.7.13.17

*2026-11-17, step 3, session 3j. Keeps D360's check of the zaaps.*

Ankama's update of 2026-11-16: client 3.7.14.18, built that day at 11:09 UTC, Unity 6000.3.16f1, serialized format 22
and Addressables 2.9.1 as before. Measured with `scripts/inspect.cs`, the extraction, and D3B's rewrite on `next`,
whose extractor gives each table's SHA-256: its tables of the two builds compared hash by hash
([client.md](../client.md#client-371418)).

- **The installation**: 20,671 bundles, as 3.7.13.17; the data tables 208 bundles, 99.1 MiB; 340,817 numbered texts.
- **The pack**, format 12, 111,873,464 bytes. The maps, their elements and graphics, the positions, sub-areas, areas,
  zaaps, items, professions, skills, breeds, hints, monsters and the icons are the same; the spell levels, spell
  states, interactives and grades the same counts.
- **The world graph** is the one table that changed: 42 vertices and 85 transitions more, none gone, 9 criteria more.
  They are area 104, La Source, whose maps 3.7.13.17 held off the graph: zaap 81, which D360 kept and counted, now
  stands on it, and no zaap is left off the graph.
- **The graphics**: the maps' bytes are the same, so the graphics learned are kept (D362).
- **The protocol**: its schema is 3.7.13.17's, byte for byte (D428).

## D428: 3.7.14.18 mapped from 3.7.13.17's pins without its own captures, and released

*2026-11-17, step 3, session 3j, chosen by the owner ("hors ligne, maintenant"), as the lead recommended it. Amends
D364 for a build whose schema is the previous build's.*

- **Measured**: `scripts/schema.cs` writes for 3.7.14.18 the bytes of 3.7.13.17's schema, SHA-256 `e383c947…`.
- **The pins carried over**: `Pins/3.7.14.18.json` holds 3.7.13.17's 99 pairs (D361); 3.7.13.17's file stays.
- **The mapping** of 3.7.14.18, format 17, made with `--without-captures`: 224 messages paired, 99 by pin, 94 by
  fields and 31 by scores, and 31 enums; audited, no failure; 14,914 bytes. Against the mapping made again for
  3.7.13.17 from the owner's 54 game captures of that build (D364), every pair of messages, fields, enums and values is
  the same; only `GameMessage`, `GameEvent` (by score) and `GameRequest` (by field) are paired otherwise than by
  their captures. No capture of 3.7.14.18 was taken: D60 is not measured again on this build.
- **Published** by `scripts/release.cs --publish` after its dry run, from this session's committed code so that the
  versions the files record name it: `client-3.7.14.18`, not marked latest, with `data-12.pack` (111,873,464 bytes,
  SHA-256 `52a02813…`), `schema-1.binpb` (170,287 bytes, 3.7.13.17's bytes) and `mapping-17.binpb` (14,914 bytes,
  `0b0611b4…`), each with its SHA-256, the GitHub digests equal to them. D3B's rewrite added its own asset to the same
  release, `client-3.7.14.18-format5.tar.gz` (its ADR 0013). Checked by `scripts/embed.cs --client-version 3.7.14.18`,
  as the release workflow takes them: the three files downloaded, their hashes and the mapping's audit hold.
- **The app**: `ClientVersion` is 3.7.14.18, so that the next app release ships the build's files (D172): 0.9.2, tagged
  on `main` once this session's pull request is merged, on the owner's go.
- **Left open**: the owner's captures of 3.7.14.18 through the app, to read its game again and measure D60; a build
  whose schema changes, Q17.
- **Rejected.**
  - Capturing first, as D364 did: the mapping it would make is the one measured equal above, and the release would
    wait on the owner's play.
  - 3.7.13.17's mapping file renamed for the new build: D361 rejected it, the pins of each build being the source.
